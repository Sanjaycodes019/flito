# Nepal address data: sources and licenses

`locations.json` and `boundaries.json.gz` are generated by
`scripts/buildNepalLocations.js` from the two public datasets below. The
downloads themselves are not committed.

## Boundaries, names and codes

**Nepal - Subnational Administrative Boundaries** (admin level 3, version v02,
valid from 2024-03-14), from the Survey Department of Nepal and the UN
Resident Coordinator's Office in Nepal, published by OCHA on the Humanitarian
Data Exchange: https://data.humdata.org/dataset/cod-ab-npl

License: Creative Commons Attribution for Intergovernmental Organisations
(CC BY-IGO).

Used for: province, district and local-level names and P-codes, and the
local-level polygons behind "Use current location". This dataset has no ward
boundaries; those come from OpenStreetMap (below).

## Ward counts, local-level categories and Nepali names

**local-states-nepal** by Sagar Gautam: https://github.com/sagautam5/local-states-nepal

License: MIT.

Used for: the number of wards in each local level (6,743 in total) and its
category (metropolitan city, sub-metropolitan city, municipality, rural
municipality). Matched to the boundaries by name and land area within each
district. Where its spelling differs from the Survey Department's, it is kept
as a search alias.

The same dataset also ships Devanagari names for every province, district
and municipality, which is where `nameNe` (and each local level's
`categoryNe`) comes from — matched to the English names above the same way,
so no separate translation step or extra license applies.

## Ward boundaries and tole names

`wards.json.gz` and `places.json.gz` are generated by
`scripts/buildNepalWards.js` from **OpenStreetMap** through the Overpass API.
Data (c) OpenStreetMap contributors, available under the Open Database
License (ODbL): https://www.openstreetmap.org/copyright

- **Wards** (`wards.json.gz`): the administrative boundary relations at admin
  level 9 and 10 (Nepal's wards), 6,696 of the 6,743 wards. Each ward is
  assigned to a local level by where it lies (not by its name), keyed by the
  ward number in its `ward` tag, and its outline is simplified to about 10 m
  and packed. A ward that can't be placed, numbered or joined into a closed
  outline is skipped, and where two outlines claim the same ward number the
  larger is kept. The build prints what it skipped.
- **Places** (`places.json.gz`): 18,729 named `place` points (neighbourhood,
  quarter, suburb, hamlet, village, locality) with their Nepali names where
  OpenStreetMap has them. "Use current location" suggests the nearest one
  within 1.2 km as the tole.

Both are volunteer-mapped: coverage is uneven and outlines are approximate, so
the app only ever presents a detected ward or tole as a suggestion to check.
This replaces the earlier per-request Nominatim lookup, so the server no
longer calls any lookup service at request time.

## Road distances

Not stored here: real road distances come from an OSRM server at request time
(`src/services/routing.js`), using OpenStreetMap roads. Set `OSRM_URL` to your
own server; the default is the public demo server.

## Rebuilding

1. Download `npl_admin_boundaries.geojson.zip` from the HDX page above and
   unzip it.
2. Clone local-states-nepal.
3. Run:

   ```
   node scripts/buildNepalLocations.js <path>/npl_admin3.geojson <path>/local-states-nepal/dataset
   node scripts/addNepaliLocationNames.js <path>/local-states-nepal/dataset
   ```

The first script refuses to write output unless it finds 7 provinces, 77
districts, 753 local levels and 6,743 wards. The second adds `nameNe` (and
`categoryNe` on local levels) to that output and reports any place it
couldn't match — expect none; it uses the same dataset directory and only
needs re-running if `local-states-nepal` renames something.

To rebuild the ward and place data (it downloads about 100 MB from Overpass
into `backend/.osm-cache`, resumable if interrupted, and takes a few minutes):

```
node scripts/buildNepalWards.js
```

Re-run it when you want fresher OpenStreetMap data. It needs the local-level
boundaries above to be built first.
